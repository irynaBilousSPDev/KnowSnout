# Промт для Claude Design — KnowSnout

Створи повноцінний дизайн-проєкт мобільного застосунку KnowSnout (iOS-first, портретна орієнтація) на основі опису нижче. Прикріплені документи "KnowSnout_Audit_Brandbook_v2.docx" і "KnowSnout_Full_Screen_Map.docx" містять повний контекст — спирайся на них.

## Продукт

KnowSnout — застосунок довіри й турботи про домашніх улюбленців для власників собак і котів в Україні та Польщі. Ключові функції: перевірка корму/рослин/породи через скан, ведення профілю тварини й щоденного догляду, підготовка до подорожей, а також спільнота (квіз, форум, блог, фото-стрічка). Тон бренду: чесний, теплий до тварин, точний до фактів, tech-clean, не клінічний.

## Кольори і шрифти — на твій розсуд

Не нав'язую конкретну палітру чи шрифт — запропонуй те, що сам вважаєш найкращим для цього бренду. Орієнтуйся на характер продукту: теплий до тварин, чесний і точний до фактів, сучасний, але не клінічний, не "стерильна клініка" і не "дитячий зоопарк з емодзі". Стиль: плоский, без зайвих градієнтів і важких тіней, заокруглені картки, мінімалістичні бордери — а конкретні кольори й шрифтову пару обери сам, виходячи з цього настрою.

## Масштабованість на перспективу

Зараз MVP — Україна й Польща, собаки й коти. Але в перспективі — усі країни й усі види домашніх улюбленців (і навіть "не зовсім домашні" компаньйони), без обмежень. Це не означає малювати зараз екрани для інших країн чи видів — але закладай дизайн так, щоб його можна було розширити: наприклад, вибір виду тварини роби як гнучкий компонент (не хардкодь жорстко "тільки собака/кіт" там, де логічно міг би бути й інший вид), і не прив'язуй візуальну систему до чогось специфічно українського чи польського, що ускладнило б вихід на інші ринки.

## Архітектура — відправна точка, не догма

Структура навігації й екранів нижче — наше поточне найкраще розуміння, продумане покроково, але не істина в останній інстанції. Ми могли щось не передбачити або помилитися в логіці. Якщо в процесі роботи побачиш кращий спосіб згрупувати екрани, інший порядок дій, чи взагалі іншу архітектуру — не бійся її змінити і поясни свою логіку. Головне — щоб кінцева структура була продуманою й функціональною для користувача, а не строго відповідала цій схемі.

## Архітектура навігації — 4 нижні таби

1. **Перевір** — сканування корму/рослини/породи + перемикач "Історія" нагорі (без окремого таба Журнал)
2. **Улюбленці** — список тварин → хаб тварини (хаб-і-спиці) → Догляд сьогодні / Профіль / Здоров'я (щеплення+ліки) / Документи+подорожі (об'єднаний чекліст, три сценарії: Вдома / В межах ЄС / Поза Шенгеном)
3. **Стрічка** — фото-пости з фільтрами, конкурси SnoutSpotlight (з посиленим CTA "Поділитися" для віральності)
4. **Спільнота** — квіз (вже сильний UX, зберегти), форум, блог

Плюс іконка профілю в хедері (не таб) → Профіль і налаштування: акаунт, мої улюбленці, сповіщення, мова та підписка, приватність і джерела даних, довідка, вийти.

## Обов'язкові уніфіковані компоненти (наскрізні по всьому застосунку)

- **Сегментований перемикач** (2–4 опції) — один стандартний компонент замість кількох різних реалізацій
- **Порожній стан фото** — квадратна плитка з пунктирною рамкою й іконкою перекресленого фото, ніколи не суцільна заливка кольором
- **Прогрес чекліста** — текст + тонка візуальна смужка або кільце, не лише цифри
- **Акордеон-форма** з прогресом для довгих форм (профіль тварини: Основне → Зовнішність → Здоров'я → Спосіб життя), тап на секцію в перегляді одразу відкриває саме її в редагуванні

## Пріоритетні екрани для першої хвилі (mobile, iOS status bar)

1. Вхід / Реєстрація
2. Перевір — хаб і Результат скану корму (score-кільце з кольором за рівнем оцінки, Pros/Cons, прив'язка до улюбленця)
3. Улюбленці — список, хаб тварини, профіль (перегляд секціями + акордеон-редагування)
4. Документи+подорожі — об'єднаний чекліст з трьома сценаріями
5. Стрічка — пости, картка учасника конкурсу з великою кнопкою "Поділитися"
6. Спільнота — квіз-хаб, форум (категорії→тред→відповідь), блог
7. Профіль і налаштування — єдиний екран з логічними секціями

## Формат результату

Повний UI kit (кольори, типографіка, компоненти) + клікабельні макети всіх перелічених екранів, послідовні між собою, готові показати як реальний дизайн-проєкт. Перед тим як почати малювати, коротко проговори свою логіку — чи бачиш щось, що варто перебудувати, об'єднати, чи додати, порівняно з описом вище.
